## Implemented

- Ordered method sites are restored from the loaded class MRO. Each records the owning module/class and the definition's file/start line when available. An unwrapped function is flagged. Class/static methods are unwrapped to their function object. Missing source slots remain in order with an explicit gap rather than disappearing. No method bodies, end lines or source-content hashes are extracted during export. Standard-library caching avoids locating a shared function repeatedly across model compositions. The exported order is definition provenance, not proof of execution, decorator effects or calls to super().
- Non-hidden source directories in selected modules and installed contributors are inventoried for `.py`/`.xml` paths, including files not directly referenced by a model class. Hidden directories and `__pycache__` are excluded. Directory links are not followed; out-of-module file links are skipped and counted. Missing module directories are gaps; unreadable directories or exceeded bounds refuse the export. Unrelated installed modules are not crawled merely because they are installed.
- New SourceFile records carry module context separately from direct model associations. Source discovery includes this context even when an exact model is requested, so model scoping does not hide its contributing modules' helpers or XML. Inventory files may be unimported Python or unloaded XML: source presence is not proof that Odoo executes/uses them. The discovery response states this explicitly. Runtime linkage still needs investigation.
- Source inventory gaps propagate into search coverage. Direct model files precede selected-module context and inherited-module context under the existing per-search budgets. An exhausted budget is incomplete coverage, never an absence verdict.
- `inspect_runtime_model(model_name, method_name=...)` exposes a specific method's ordered sites without enabling speculative legacy workflow/access tools. Source locations remain hints: search and read the current fingerprint-checked fragments before explaining behavior. Default model-fact output still prioritizes security metadata over a potentially long method listing.

## Use and bounds

Re-run the existing Odoo-shell export command from `runtime_metadata_graph_log.md` to replace the previous simplified snapshot, then restart the backend with the existing explicit path/instance key. Older snapshots load for compatibility, but do not acquire the restored method/source inventory until exported again. No `.env` was read or changed here.

Two operator environment settings were added: `CI_RUNTIME_GRAPH_MAX_SOURCE_FILES` (default 10000) and `CI_RUNTIME_GRAPH_MAX_SOURCE_ENTRIES` (default 50000). `CI_RUNTIME_GRAPH_MAX_ROWS` also bounds the total exported method-definition sites. All bounds must be positive; excess fails rather than silently publishing an incomplete bounded inventory. Per-question source file/byte/fragment limits remain separately configurable through the existing CI_SOURCE_SEARCH settings. A complete scan of the bounded inventory is not complete Odoo behavior coverage.
