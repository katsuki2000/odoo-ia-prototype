## Section 1203 : audit transversal des outils CI et constat de structure du code (lecture seule)

Date : 09/10/2026
**Mandat (pmm)** : « pas que pour ce cas, je te demande de regarder carrément le code », puis demande d'inscrire les constats dans le journal et remarque sur l'éparpillement des outils, du graphe, de la boucle et de l'extraction.
**Périmètre de lecture** : wrappers exposés dans `code_intelligence/agent/tools/`, dispatch d'appels dans `agent/loop.py`, gardes dans `agent/dispatch_guards.py`, et implémentations des règles d'accès, navigation/bouton, workflow, extraction des contraintes et introspection. Audit statique ; aucun outil n'a été exécuté sur une instance ni aucune donnée sensible lue ; aucun fichier source n'a été modifié pendant cet audit.
**Défauts vérifiés, par priorité** :
1. **Risque de lecture de fichier hors corpus** : `read_source_code` appelle `read_precise_source_code(filepath, ...)`; cette fonction accepte un chemin existant (`Path(filepath_str)`) sans vérifier qu'il reste sous les répertoires d'addons autorisés. La boucle exécute cet outil directement ; le garde `gate_observation` masque certains motifs de bypass mais n'est pas une liste d'autorisation de chemins. Un appel peut donc lire tout fichier que le processus peut lire (potentiellement `.env`/secrets). Le plafond de lignes ne limite que la taille par appel. Aucun fichier n'a été lu pour confirmer la présence de secrets.
2. **Groupes inconnus réduits à aucun groupe pour `ir.rule`** : `_override_user_groups_arg` convertit `resolved_user_group_xmlids=None` en JSON `[]` pour `evaluate_record_rules`; `evaluate_record_rules` traite ensuite `None` comme `[]`. Il ignore donc les règles de groupe et peut conclure qu'aucune restriction de groupe ne s'applique, alors que l'identité/groupes ne sont pas connus. La correction de la section 1202 ne couvre que les pré-dispatchs UI, pas ce chemin d'accès.
3. **Erreur Semgrep confondue avec absence de résultat** : `run_semgrep_analysis` renvoie `[]` si la configuration manque, si Semgrep renvoie un code d'échec, ou si une exception/timeout survient. `_compose_data_constraints_summary` transforme toute liste vide en « aucun motif détecté » avec confiance élevée. Le contrat ne distingue pas succès sans finding et analyse échouée.
4. **Chemin de graphe pouvant être fabriqué** : `explain_decision_path` valide la forme JSON mais `_explain_decision_path_impl` ne vérifie pas que les nœuds/arêtes existent ; une arête absente reçoit le type par défaut `CONNECTED_TO` et est présentée comme une relation.
5. **Ambiguïté de bouton non signalée** : `button_execution_path` choisit `candidate_transitions[0]` comme méthode lorsqu'il y a plusieurs correspondances exactes, puis ne conserve que les transitions de cette méthode. L'ordre du graphe devient un choix sémantique non justifié.
6. **Surcharge `get_view` assimilée à une injection de bouton** : le repli `search_dynamic_view_or_menus` conclut à une injection dynamique de boutons lorsqu'il trouve une surcharge `get_view`/`fields_view_get`, sans vérifier le corps de la méthode ; cette branche ne produit pas d'evidence.
7. **Rôle technique non universel** : `resolve_technical_name_to_role` utilise une table statique de quelques groupes natifs, puis fabrique un libellé depuis le slug pour les groupes non répertoriés. Les groupes custom et les traductions d'une instance ne sont pas introspectés ; le libellé peut ressembler à une traduction valide sans en être une.
**Constat d'architecture** : le dépôt a déjà des frontières utiles (`agent/tools` pour les wrappers, `extractor` pour XML/Python/CSV/JS/manifest, `graph` pour construction/chargement/version/traductions, `rules` pour les analyses de domaine). Il n'est donc pas entièrement « sans structure ». Mais `agent/loop.py` porte exécution des outils, boucle ReAct et orchestration du tour ; `predispatch_access.py` et `predispatch_structure.py` regroupent de nombreux dispatchers ; certains gros modules `rules` mélangent analyse, rendu et corrections de réponse. Inversion de dépendance observée : des règles importent `agent.context` / `agent.tool_helpers` pour budgets et question courante, ce qui fait dépendre le domaine du runtime agent. Plusieurs docstrings exposent des anciens chemins/noms (`ci_agent_node`, `deterministic`) qui ne correspondent pas à l'arborescence actuelle. Le problème est donc la séparation de responsabilités, quelques dépendances inversées et une nomenclature de migration incohérente, pas l'absence totale de dossiers dédiés.
**Piste de structure (non appliquée)** : garder `agent/tools` comme adaptateurs sans logique métier ; décomposer `agent/loop.py` en modules d'exécution (dispatch d'outils, boucle ReAct, orchestration du tour) sans créer un package `loop/` par principe ; garder les extracteurs dans `extractor` et la construction/sérialisation du graphe dans `graph`; organiser les analyses par domaine (`access`, `ui`, `workflow`, `source_analysis`) dans `rules` et séparer les post-traitements de réponse de l'analyse factuelle. Toute migration devrait être progressive, avec imports compatibles et tests, sans déplacer un fichier uniquement pour le faire correspondre à son nom.
**Suite suggérée (pas encore autorisée/appliquée)** : traiter d'abord le confinement de `read_source_code`, puis le statut inconnu des groupes dans `evaluate_record_rules`, ensuite le statut d'échec Semgrep. Ajouter des tests hermétiques de régression pour les trois. Les ambiguïtés de bouton, validation des chemins de graphe, repli `get_view` et résolution de rôles sont ensuite à corriger. La refonte de structure est un chantier distinct ; ne pas faire de déplacements massifs pendant ces fixes.
**Fichiers consultés** : `code_intelligence/agent/tools/{access,analysis,introspection,structure}.py`, `code_intelligence/agent/loop.py`, `code_intelligence/agent/dispatch_guards.py`, `code_intelligence/rules/{access_evaluator,record_rules,data_constraints,button_path}.py`, et l'implémentation de recherche dynamique de vues.
